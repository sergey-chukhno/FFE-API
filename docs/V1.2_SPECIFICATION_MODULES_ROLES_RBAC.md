## 1. Vue d'Ensemble & Objectifs

La version **v1.2** fait évoluer l'application d'un outil unitaire de scraping vers un **ERP associatif complet et sécurisé** pour **Marseille-Échecs**.  
Elle instaure un modèle de contrôle d'accès basé sur les rôles (**RBAC - Role-Based Access Control**), garantissant que chaque bénévole, salarié ou intervenant du club n'accède qu'aux données et fonctionnalités strictement nécessaires à sa mission.

### Choix de la Stack d'Authentification : Better-Auth
* **Souveraineté des données** : Toutes les données d'utilisateurs, sessions et rôles sont stockées dans notre propre base **PostgreSQL locale (port 5433) / Neon Serverless**.
* **Zero Vendor Lock-in** : Pas de dépendance envers un service SaaS externe payant (type Clerk ou Auth0).
* **Double méthode de connexion** :
  1. Identifiants classiques : **Email + Mot de passe** (hachage sécurisé avec sel unique).
  2. Fournisseur moderne : **Google OAuth** (authentification en 1 clic avec le compte Google du club ou personnel).
* **Intégration Next.js 14 App Router** : Gestion native des sessions en Edge Middleware, Server Components et Route Handlers.

## 2. Définition des 4 Rôles Utilisateurs

### 1. `director` (Directeur Sportif)
* **Mission** : Pilotage sportif, validation des affiliations FFE, homologation des équipes et supervision globale des entraînements/analytics (statistiques) du club; 
* **Périmètre d'accès** :
  * ✅ **Vérification des Licences (Excel)** : Plein accès (dépôt de fichiers, analyse vectorielle, filtrage A/B, exports).
  * ✅ **Recherche FFE Joueur** : Plein accès (base locale + scraping en direct).
  * ✅ **Gestion des Équipes** : Plein accès (composition, ordre des échiquiers, validation).
  * ✅ **Synchronisation du Club** : **Accès Exclusif** (seul le directeur et le superadmin peuvent forcer l'aspiration des licenciés).
  * ✅ **Analytique & Entraînements** : **Lecture globale** sur tous les cours et tous les entraîneurs du club.
  * 👁️ **Inventaire** : Consultation seule (lecture du stock et des alertes).
  * ❌ *Pas de gestion des comptes utilisateurs ni des logs techniques*.

### 2. `coach` (Entraîneur du Club)
* **Mission** : Encadrement des groupes de cours, préparation des rondes de match.
* **Périmètre d'accès** :
  * ✅ **Recherche FFE Joueur** : Plein accès pour consulter le classement d'un élève ou adversaire.
  * 👁️ **Module Équipes** : Consultation seule (read-only) pour voir les feuilles de match.
  * ✅ **Mes Cours & Entraînements** : **Restreint exclusivement à ses propres classes** (`coach_id`). Saisie des présences et suivi des élèves de ses cours.
  * ❌ **Interdit** : Vérification par lot Excel, Synchronisation du club, Gestion d'inventaire, Cours des collègues.

### 3. `secretary` (Secrétaire du Club)
* **Mission** : Accueil du public, gestion de la vie du club, tenue du bar/buvette, vente de matériel et merchandising.
* **Périmètre d'accès** :
  * ✅ **Recherche FFE Joueur** : Plein accès pour vérifier l'affiliation d'un adhérent qui se présente au club.
  * ✅ **Module Inventaire** : **Plein accès CRUD** (Ajouter, Modifier, Supprimer un article, ajuster les stocks, consulter l'historique des ventes).
  * 🔔 **Alertes de Réassort** : Réception des notifications (badge sur dashboard + alerte e-mail).
  * ❌ **Interdit** : Vérification des licences par lot, Synchronisation du club, Gestion des équipes, Entraînements.

### 4. `superadmin` (Développeur / Administrateur Système)
* **Mission** : Maintenance de l'application, supervision des performances, gestion de la sécurité et des accès.
* **Périmètre d'accès** :
  * 🛡️ **Plein accès technique à tous les modules**.
  * ✅ **Gestion des Utilisateurs** : Création de comptes, assignation et modification des rôles, réinitialisation de mots de passe.
  * ✅ **Logs & Audit Trails** : Consultation des logs d'erreurs, des logs de synchronisation (`sync_logs`) et de l'historique d'inventaire.

## 4. Spécification des Nouveaux Modules

### A. Module Inventaire (Secrétariat & Boutique)
* **Catégories d'articles gérées** :
  1. `BOUTIQUE` : Échiquiers en bois, pendules DGT, t-shirts, pulls, écharpes du club.
  2. `BUVETTE` : Boissons fraîches, café, thé, snacks, gâteaux pour les tournois du week-end.
  3. `BIBLIOTHEQUE` : Livres d'échecs, revues, manuels tactiques prêtés ou vendus.
* **Champs d'un article (`inventory_items`)** :
  * `id` : Identifiant UUID unique.
  * `name` : Intitulé de l'article (ex: "Échiquier de compétition DGT").
  * `category` : Enum (`BOUTIQUE`, `BUVETTE`, `BIBLIOTHEQUE`).
  * `stock_quantity` : Quantité disponible en réserve.
  * `unit_price` : Prix unitaire en euros (ex: 2.50 €).
  * `alert_threshold` : Seuil d'alerte minimale (ex: si stock < 5 $\to$ alerte).
  * `description` : Descriptif ou localisation de stockage.
  * `updated_at` & `updated_by` : Traçabilité de la dernière modification.
* **Système d'alerte de réassort** :
  * **Sur le tableau de bord** : Badge d'alerte visuel avec pastille clignotante orange/rouge dès qu'un produit passe sous son seuil.
  * **Par e-mail** : Notification automatique envoyée au secrétariat lors du passage sous le seuil critique.

### B. Module Cours & Entraînements (`classes`)
* **Champs d'un cours** :
  * `id` : Identifiant unique du groupe.
  * `name` : Nom du cours (ex: "Poussins Débutants", "Perfectionnement Adultes").
  * `day_of_week` : Jour de la semaine (ex: "Lundi", "Mardi", "Mercredi", "Samedi", "Autre").
  * `start_time` & `end_time` : Plage horaire (ex: "14:00 - 15:30").
  * `level` : Niveau (Débutants, Initiés, Élites, Pôle Espoir, Autre).
  * `coach_id` : Clé étrangère reliant le cours au compte de l'entraîneur (`users.id`).
  * `active` : Statut du cours.

## 5. Modélisation Relationnelle PostgreSQL (DDL)

```sql
-- 1. Table des Utilisateurs
CREATE TABLE IF NOT EXISTS users (
  id VARCHAR(36) PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  email_verified BOOLEAN DEFAULT FALSE,
  image TEXT,
  role VARCHAR(50) NOT NULL DEFAULT 'coach', -- 'superadmin', 'director', 'coach', 'secretary'
  password_hash TEXT,
  phone VARCHAR(50),
  active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_users_email ON users(email);
CREATE INDEX IF NOT EXISTS idx_users_role ON users(role);

-- 2. Table des Sessions Better-Auth
CREATE TABLE IF NOT EXISTS sessions (
  id VARCHAR(36) PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token VARCHAR(255) UNIQUE NOT NULL,
  expires_at TIMESTAMPTZ NOT NULL,
  ip_address VARCHAR(100),
  user_agent TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3. Table des Comptes Externes (Google OAuth)
CREATE TABLE IF NOT EXISTS accounts (
  id VARCHAR(36) PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  account_id VARCHAR(255) NOT NULL,
  provider_id VARCHAR(50) NOT NULL, -- 'google', 'credential'
  access_token TEXT,
  refresh_token TEXT,
  expires_at TIMESTAMPTZ,
  password TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 4. Table des Cours / Classes (Entraîneurs)
CREATE TABLE IF NOT EXISTS classes (
  id SERIAL PRIMARY KEY,
  name VARCHAR(150) NOT NULL,
  day_of_week VARCHAR(20) NOT NULL,
  start_time VARCHAR(10) NOT NULL,
  end_time VARCHAR(10) NOT NULL,
  level VARCHAR(50) NOT NULL DEFAULT 'Tous niveaux',
  coach_id VARCHAR(36) REFERENCES users(id) ON DELETE SET NULL,
  active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_classes_coach_id ON classes(coach_id);

-- 5. Table des Articles d'Inventaire (Secrétariat)
CREATE TABLE IF NOT EXISTS inventory_items (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  category VARCHAR(50) NOT NULL, -- 'BOUTIQUE', 'BUVETTE', 'BIBLIOTHEQUE'
  stock_quantity INTEGER NOT NULL DEFAULT 0,
  unit_price NUMERIC(8, 2) NOT NULL DEFAULT 0.00,
  alert_threshold INTEGER NOT NULL DEFAULT 5,
  description TEXT,
  last_restocked_at TIMESTAMPTZ,
  updated_by VARCHAR(36) REFERENCES users(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_inventory_category ON inventory_items(category);

-- 6. Journal d'Audit des Mouvements de Stock
CREATE TABLE IF NOT EXISTS inventory_logs (
  id SERIAL PRIMARY KEY,
  item_id INTEGER NOT NULL REFERENCES inventory_items(id) ON DELETE CASCADE,
  change_amount INTEGER NOT NULL, -- Ex: -2 (vente), +20 (réassort)
  reason VARCHAR(100) NOT NULL,   -- 'VENTE', 'REASSORT', 'INVENTAIRE_MANUEL', 'PERTE'
  performed_by VARCHAR(36) REFERENCES users(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## 6. Architecture de Sécurité à 3 Cercles

```
[ Requête Navigateur ]
         │
         ▼
[ Cercle 1 : Edge Middleware Next.js ]
   ├── Vérifie la présence du token de session Better-Auth
   ├── Redirige les anonymes vers /login
   └── Bloque préventivement l'accès aux sous-chemins selon le rôle
         │
         ▼
[ Cercle 2 : Route Handlers & Server Guards ]
   ├── Décode l'identité de l'utilisateur en base
   ├── Valide la permission exacte (ex: hasPermission(user, 'sync:execute'))
   └── Rejette avec HTTP 403 Forbidden en cas d'usurpation
         │
         ▼
[ Cercle 3 : Rendu Conditionnel UI (Client-Side) ]
   ├── Affiche ou masque les onglets de la TabNavigation
   ├── Désactive les boutons non autorisés (ex: bouton Synchroniser)
   └── Affiche des alertes contextuelles adaptées
```
