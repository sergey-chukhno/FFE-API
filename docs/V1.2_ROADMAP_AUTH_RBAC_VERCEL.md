## 1. Vision & Objectifs de la Version 1.2

La version **v1.1** a doté Marseille-Échecs d'un moteur de scraping autonome officiel FFE, d'une base de données PostgreSQL haute performance (< 25 ms pour 1 000 joueurs), et d'une interface graphique moderne avec Glassmorphisme.

La version **v1.2** a pour mission de transformer cette application en une **plateforme collaborative sécurisée d'entreprise**, prête pour la production et adaptée aux différents profils de l'association :
1. **Authentification moderne et souveraine (Better-Auth)** : Connexion par e-mail + mot de passe sécurisé et support de Google OAuth, avec données hébergées dans notre base PostgreSQL.
2. **Modèle de permissions fines (RBAC)** : 4 rôles opérationnels étanches (`director`, `coach`, `secretary`, `superadmin`).
3. **Nouveau module Métier : Inventaire & Réassort** : Gestion complète des articles du club (Boutique, Buvette, Bibliothèque) pour le secrétariat, avec alertes de stock critique.
4. **Optimisation concurrente du scraper** : Réduction du temps de synchronisation de 59s à **< 8 secondes** pour respecter les quotas de durée du plan gratuit **Vercel Hobby**.
5. **Déploiement en Production Cloud** : Liaison du nouveau compte GitHub Marseille-Échecs à Vercel et configuration de Neon Serverless PostgreSQL.

## 3. Découpage des Étapes de Réalisation (Étapes 8 à 11)

### Étape 8 : Modélisation SQL & Moteur d'Authentification Better-Auth
* **Objectifs** :
  1. Installer et configurer la bibliothèque moderne `better-auth` avec le pilote PostgreSQL `pg`.
  2. Créer le schéma DDL SQL pour la gestion des utilisateurs, des sessions, des cours (`classes`) et de l'inventaire (`inventory_items`, `inventory_logs`).
  3. Mettre en place le hachage sécurisé des mots de passe et préparer l'adaptateur pour Google OAuth.
  4. Créer un script de seeding pour initialiser les 4 comptes de test du club (`admin@marseille-echecs.com`, `directeur@...`, `coach@...`, `secretaire@...`).
  5. Écrire des tests automatisés complets pour la validation de la création de compte, de la connexion et de la vérification des rôles.
* **Livrables** : Code source, script de seed, tests unitaires verts, rapport `docs/CRs/V1.2_ETAPE_8_VALIDATION.md`.

---

### Étape 9 : Écran de Connexion Glassmorphique & Sécurisation des Accès (Middleware + API Guards)
* **Objectifs** :
  1. Concevoir la page de connexion `/login` en Glassmorphisme reprenant la charte graphique officielle de Marseille-Échecs (dégradés bleu royal, Day/Dark mode, bouton de connexion Google).
  2. Implémenter le middleware Next.js Edge pour intercepter les requêtes, rediriger les visiteurs non connectés vers `/login` et filtrer les accès non autorisés.
  3. Sécuriser les Route Handlers backend avec des gardes stricts de permissions :
     * `/api/verify-batch` : restreint à `director` et `superadmin`.
     * `/api/cron/sync-club` : restreint à `director` et `superadmin`.
     * `/api/players/search` : accessible à tous les rôles connectés.
  4. Écrire des tests automatisés validant les rejets `401 Unauthorized` et `403 Forbidden` pour les utilisateurs non autorisés.
* **Livrables** : Page `/login`, middleware de protection, gardes d'API, tests automatisés verts, rapport `docs/CRs/V1.2_ETAPE_9_VALIDATION.md`.

---

### Étape 10 : Module Inventaire & Interface Adaptative selon le Rôle
* **Objectifs** :
  1. Développer l'interface complète du module **Inventaire** dédiée au secrétariat :
     * Liste des articles avec badges de catégories (`BOUTIQUE`, `BUVETTE`, `BIBLIOTHEQUE`).
     * Ajout, modification, suppression d'articles (CRUD).
     * Incrémentation/décrémentation rapide du stock (entrées/sorties).
     * Seuil d'alerte de réassort avec indicateur visuel immédiat (badge clignotant).
     * Préparation du service d'envoi d'e-mails d'alerte de stock.
  2. Rendre la barre de navigation `TabNavigation` **dynamique et adaptative** :
     * Le directeur voit les licences, la recherche, les équipes, la synchronisation et la consultation de tous les cours.
     * L'entraîneur voit la recherche, la consultation des équipes et l'accès exclusif à ses propres cours.
     * La secrétaire voit la recherche et le module inventaire complet.
  3. Restreindre l'affichage et l'action du bouton *« Synchroniser »* dans l'en-tête au seul Directeur Sportif (et Superadmin).
  4. Écrire les tests automatisés du module inventaire et du rendu conditionnel des permissions.
* **Livrables** : Module inventaire, navigation adaptative, tests verts, rapport `docs/CRs/V1.2_ETAPE_10_VALIDATION.md`.

---

### Étape 11 : Optimisation Concurrente du Scraper & Déploiement Vercel
* **Objectifs** :
  1. Paralléliser la fonction de scraping `fetchAllClubMembers` via un pool de requêtes concurrentes (`Promise.all` par lot de 3 à 4 pages) pour faire passer l'aspiration des 1 625 membres de 59s à **< 8 secondes**, garantissant la conformité stricte avec les quotas du plan gratuit **Vercel Hobby**.
  2. Mettre à jour la configuration Vercel (`vercel.json`) avec `maxDuration: 60` et la déclaration du cron quotidien nocturne à 03h00 UTC.
  3. Guider la création du nouveau dépôt GitHub pour l'organisation Marseille-Échecs et sa liaison au projet Vercel.
  4. Configurer la base de production Neon Serverless PostgreSQL et injecter les variables d'environnement (`DATABASE_URL`, `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_ID`, `CRON_SECRET`).
  5. Réaliser la session finale de smoke tests en production réelle.
* **Livrables** : Scraper optimisé, application déployée en ligne sur Vercel, tests de production validés, rapport `docs/CRs/V1.2_ETAPE_11_VALIDATION.md`.
